## 실제 Minecraft 클라이언트 확인

별도 `work/fabric-client` 디렉터리의 개발 클라이언트에서 확인했습니다. 평소 사용하는 `.minecraft`의 월드에는 접속하지 않았습니다.

1. 실제 네이티브 화면에서 다섯 원본 스킨을 WIDE 모델의 3D 미리보기로 표시했습니다. 한글 이름·소개 대사·카드 선택 색과 마우스 성격 툴팁을 확인했습니다.
2. 새 싱글플레이 테스트 월드에 들어갔을 때 사용자 조작 없이 선택창이 열렸고 싱글플레이가 일시 정지되었습니다.
3. 게임 안 연결 설정에 별도 로컬 실행기 폴더를 입력하고 도로롱을 선택했습니다. 클라이언트 설정과 실제 Node 실행기 양쪽에 동일한 월드 키·`characterId=doro`가 저장되었고 `helper_selected` 이벤트 하나가 기록되었습니다. 소유자 메시지나 게임 작업은 생성되지 않았습니다.
4. 확정 후 게임으로 복귀하며 선택 완료 안내가 표시되었습니다. **H 키로 다시 열어 도로롱이 유지됨**을 확인했습니다.
5. 테스트 클라이언트를 종료하고, 테스트 설정을 백업한 뒤 월드 선택 항목만 비운 상태로 같은 기존 저장 월드에 재접속했습니다. 모드를 나중에 설치한 월드와 같은 조건에서 선택창이 자동으로 열렸습니다. 월드 저장 파일은 이 테스트 준비 과정에서 편집하지 않았습니다.
6. GUI 배율 2와 3(1280×800 클라이언트)에서 모든 카드·이름·확정 버튼과 설명 영역을 확인했습니다. 기본 튜토리얼 알림과 겹친 메뉴 버튼은 왼쪽 위로 옮겨 빌드했습니다.
7. 수정된 일시 정지 메뉴의 버튼을 실제로 클릭해 선택창에 재진입했습니다. 기존 월드에서 젬짱으로 변경한 값은 클라이언트와 실행기 모두에 변경 번호 2로 저장되었고, 소유자 메시지 0개·게임 작업 0개를 유지했습니다.

`images/character-selector.png`는 실제 게임의 F2 스크린샷입니다. 화면 목업이 아닙니다.

## 검증 범위의 한계

- 선택 화면과 로컬 실행기까지의 전달을 검증했습니다. 로그인된 실제 LLM이 캐릭터 말투로 답하는 모델 추론은 실행하지 않았습니다.
- 실제 플레이 서버·봇 계정은 미설정입니다. 이 검증은 자율 플레이나 생존 성공, Minecraft 채팅과 실제 모델 대화의 종단 검증을 뜻하지 않습니다.
- 선택창 스킨은 계정 스킨 변경 기능이 아닙니다. 실제 봇에게 다른 플레이어가 보는 외형 적용은 포함하지 않습니다.
- 멀티플레이 원격 서버, 다른 모드와의 충돌, 다른 운영체제의 UI는 아직 검사하지 않았습니다. 하나의 서버 주소는 하나의 선택을 공유합니다.
- 실제 개발 클라이언트에는 Windows 성능 카운터 경고와 개발 로그인에 대한 Realms 인증 경고가 있었습니다. 선택창 모드의 로딩·렌더링·저장 예외는 발생하지 않았습니다.

Gradle의 공식 배포 체크섬은 wrapper 설정과 `character-verification.json`, 설치 JAR 및 Fabric API 체크섬은 `dist/SHA256SUMS.txt`를 참고합니다. 설치 ZIP 안에서는 `SHA256SUMS.txt`가 루트에 있습니다. 상세 자동 검사 보고서는 `fabric-mod/build/reports/tests/test/index.html`에 있습니다.
